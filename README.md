# dvorzhik.site — программы и сервисы

Лендинг с программами и сервисами Александра Дворжицкого (Дворжика):
DrawStory, GeminiPoint, Personal Sky, ZenReader, Yamometer, Yuri Vizbor AI,
SeaBlitz, а также архив ранних экспериментов.

Сайт — статический (один `index.html` + папка `images`), публикуется через
GitHub Pages на кастомном домене **https://www.dvorzhik.site/**.

## Структура

```
index.html      # лендинг: шапка, карточки программ, подвал
more.html       # страница «Узнать больше» (?id=drawstory, geminipoint, …)
CNAME           # кастомный домен для GitHub Pages: www.dvorzhik.site
images/         # скриншоты программ, иконки и подложка шапки
scripts/        # вспомогательные скрипты подготовки картинок
```

## Как добавить новую программу

1. Положите картинку в `images/`, приведя её к 11:6 (см. ниже).
2. Скопируйте в `index.html` блок `<article class="card">…</article>` и вставьте
   его **первым** в секции «Программы» — новые программы идут сверху. Замените
   картинку, заголовок, описание, бейджи и ссылку.
3. Добавьте программу в список `PROGRAMS` в `more.html` — тоже первым, чтобы
   порядок совпадал с порядком карточек.

> Бейджи в карточке рассчитаны на максимум три штуки и должны укладываться в одну
> строку даже в самой узкой карточке (три колонки в окне ~920 css-px) — так сейчас
> у SeaBlitz (`Игра` + `Веб-приложение` + `Telegram-bot`). Поэтому у `.badge`
> компактные размеры: шрифт `0.68rem`, отступы `3px 5px`, зазор между бейджами
> `3px`. Если их увеличить, третий бейдж перенесётся на вторую строку; при этом
> чипы фильтров в шапке — это отдельный класс `.tag`, он не затронут.

## Картинки карточек

Карточки показывают картинку в рамке **11:6** (`aspect-ratio: 11 / 6` в
`index.html`, `object-fit: cover`), поэтому файлы в `images/` тоже приводят к
11:6 — тогда CSS ничего не срезает. Рабочий размер — 1100×600: это больше двух
ширин карточки (~500 css-px), то есть с запасом для Retina-экранов. Исключение —
ZenRead: там лежит готовая промо-картинка 1024×559, как есть (см. ниже); апскейл
до 1100×600 добавлял ей заметный артефакт интерполяции.

Любой исходник приводится к 11:6 скриптом `scripts/make_card_image.py`: он
вписывает картинку в холст целиком (по длинной стороне) и доливает свободные
полосы — содержимое не режется, в отличие от центрального кадрирования. Исходники
лежат в соседнем репозитории `vibecoding/images/`.

```powershell
# промо-картинка GeminiPoint: исходник уже 11:6 — полос не будет
python scripts/make_card_image.py --source ..\vibecoding\images\geminipoint_art.jpg --output images\geminipoint.jpg
# страница Визбора на кремовом фоне: полосы по бокам берут цвет верхнего края
python scripts/make_card_image.py --source ..\vibecoding\images\vizbor.png --output images\vizbor.jpg --fill top
# картинка Yamometer уже 11:6 — полос не будет вовсе
python scripts/make_card_image.py --source ..\vibecoding\images\Yamometer.jpg --output images\yamometer.jpg
# SeaBlitz: полосы по бокам — бумажный фон страницы
python scripts/make_card_image.py --source ..\vibecoding\images\SeaBlitz.jpg --output images\seablitz_app.jpg --fill top
# Personal Sky: иллюстрация 1024×572 — полосы по бокам, отражение неба без шва
python scripts/make_card_image.py --source ..\vibecoding\images\personal_sky_art.jpg --output images\personal_sky.jpg --fill mirror
# DrawStory: иллюстрация уже в пропорции 11:6 — просто масштабируется до холста
python scripts/make_card_image.py --source ..\vibecoding\images\drawstory_art.jpg --output images\drawstory.jpg
# ZenRead: готовая промо-картинка уже 11:6 (1024×559) — кладётся как есть,
# без прогонов через скрипт: апскейл до 1100×600 добавлял артефакт
# Copy-Item ..\vibecoding\images\zenread.jpg images\zenread.jpg
```

Ключи: `--fill edges` (по умолчанию — средний цвет соответствующего края),
`--fill top` / `--fill bottom` (один край на все полосы) и `--fill mirror`
(отражение прилегающего края — продолжает градиент без шва). Посмотреть, что
скрипт сделает, не записывая файл: `--diagnose`; другой холст: `--canvas 880x480`.
Если исходник уже в пропорции 11:6 (например 1024×559), полос не будет вовсе —
картинка просто масштабируется до холста.

Если у программы нет скриншота, а есть только логотип, картинку кладут на
прозрачный холст и подключают с классом `is-logo` — тогда тема не рисует
белую подложку:

```html
<img class="card-img is-logo" src="images/logo.png" alt="Название" loading="lazy" />
```

Раньше круглый логотип из квадратного исходника (белый фон и мягкая тень по
краям) вырезал отдельный скрипт: находил окружность по строкам картинки, резал
по ней с мягким краем и клал результат на прозрачный холст 11:6. Сейчас он не
нужен и удалён — у ZenRead обычная промо-картинка (`images/zenread.jpg`).

## Шапка сайта

Сверху страницы нет логотипа-картинки: фон шапки — подложка
`images/programs_fon.jpg` (стол «мастерской» с ноутбуком). Она подключена прямо
в CSS у `.hero`, нижним слоем, а поверх неё лежат светлая вуаль и мягкое тёплое
свечение акцентом:

```css
background:
  radial-gradient(900px 300px at 50% -120px, rgba(202, 138, 4, 0.16) 0%, rgba(202, 138, 4, 0) 70%),
  linear-gradient(180deg, rgba(255, 255, 255, 0.64) 0%, rgba(248, 250, 252, 0.86) 100%),
  url('images/programs_fon.jpg') center center / cover no-repeat,
  #f8fafc;
```

Вуаль приглушает картинку: она заметна, но не спорит с заголовком — текст
остаётся контрастным. Если подложку менять, достаточно положить новый файл на
место старого: пропорция не критична (`cover` сам обрежет края), но чем шире
исходник, тем меньше кроп по бокам. Текущий — 1024×254 (≈4:1), при ширине шапки
1080 css-px он виден почти без потерь. Отдельного тега в HTML для подложки нет,
поэтому менять разметку не придётся.

## Локальный просмотр

Достаточно открыть `index.html` в браузере, либо:

```powershell
python -m http.server 8000
```

## Публикация

GitHub Pages настроен на ветку `main`, папку `/ (root)`, с файлом `CNAME`.
Кастомный домен `www.dvorzhik.site` привязан в настройках репозитория
(Settings → Pages).

> Важно: домен `dvorzhik.site` обслуживается DNS-серверами `reg.ru`.
> Чтобы сайт открывался, в панели reg.ru записи `dvorzhik.site` и `www`
> должны указывать на GitHub Pages (A-записи `185.199.108–111.153` и
> CNAME `dvorzhik.github.io`), а редирект на `dvorzhik.ru` — отключён.
> Записи поддоменов `drawstory` и `geminipoint` при этом остаются
> указывать на прежний сервер (`217.149.24.198`).
